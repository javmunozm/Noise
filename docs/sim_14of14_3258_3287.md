# 14/14 simulation — tickets needed per series (3258–3287)

Run 2026-10-04 in a cloud session (not a production system). Question: for each of the latest 30 series, how many distinct tickets must be played before one matches **any** of the series' 7 events exactly (14/14)?

## Method

- Targets: the 7 events of each series 3258–3287. 3286 and 3287 come from user-supplied results (not yet ingested via `add_series.py`).
- Tickets are streamed one at a time; duplicates are skipped, so the count is **distinct tickets played**. The count stops at the first exact match; `Event` is the event it matched.
- **Random**: uniform random 14-of-25 tickets.
- **CB pair**: ticket A sampled with a tilt toward the CondScore ranking (z-scored CondScore × 0.5 + Gumbel noise, history strictly before the series), then ticket B = A's contrarian (the 11 numbers A left out + A's 3 weakest by CondScore), emitted as pairs A, B, A, B, … — the same contrarian rule as `bsadb_update.py`. Run with 4 seeds (3288, 11, 22, 33).
- Theory (independent draws): for any ticket order, the number of distinct tickets until the first hit on one of 7 events has mean (4,457,400+1)/8 = **557,175**, median **420,228**, 10th percentile 66,589, 90th percentile 1,249,473.

## Findings

- **No series reached 14/14 within 1,000 tickets** in any run. The fastest hit across all 150 runs was 3,866 tickets (series 3261, random).
- **The CB-pair generator does not need fewer tickets.** Its first run looked faster (median 229,465), but the other three seeds gave 512,915 / 519,472 / 411,361. Across all 120 CB-pair runs the mean is 551,766 vs 557,175 theory, and 63/120 runs beat the theoretical median (one-sided binomial p = 0.32). The first run was luck.
- **The count depends on the random order, not on the series.** The same series takes very different counts across seeds (e.g. 3268 took 26,517 / 1,100,499 / 54,236 / 1,657,587 across the four CB-pair seeds), so no series is inherently "easy".
- Why no generator can do better on average: when draws are independent, a uniformly random target sits at an average position of (N+1)/2 in **any** ticket order, so the first hit on 7 events averages (N+1)/8 tickets whatever the ordering rule. A rule can only beat this if the draws are predictable, which no test in this repo has found.
- The CB-pair stream repeats itself heavily: the seed-3288 run generated 52.5M tickets to reach the distinct counts above.
